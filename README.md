# transunion-pdf-engine

A standalone, reusable PDF generation engine that turns a raw **TransUnion
CIBIL** credit report API response into a professional, print-ready PDF
report using [ReportLab](https://www.reportlab.com/).

The engine is **framework-agnostic**: `transunion_pdf_engine/` has no dependency on
Django, Flask, or any web framework. The only Django-aware code lives in
`services/transunion_pdf_service.py`.

> Architecturally inspired by a companion CRIF PDF engine (parser /
> generator / models / sections split), but every parsing rule here is
> derived from the real TransUnion CIBIL JSON shape and cross-checked
> against `docs/sample_report.pdf.pdf` -- see `docs/JSON_TO_PDF_MAPPING.md`
> for the full field-by-field trace. No CRIF-specific logic was ported.

## Installation

```bash
pip install -r requirements.txt
```

Requirements: Python 3.10+, `reportlab`, `svglib` (renders the local CIBIL
logo SVG), `pypdf` (for tests). Django is **not** required to use
`transunion_pdf_engine` directly; it is only needed if you use
`services/transunion_pdf_service.py` inside a Django project. All fonts and
the logo are loaded from `transunion_pdf_engine/assets/` -- nothing is downloaded and
no system fonts are required.

## Usage

### Quick start

```python
import json
from transunion_pdf_engine import generate_report

with open("input/transunion_response.json", encoding="utf-8") as f:
    raw_json = json.load(f)

pdf_path = generate_report(raw_json, "output/report.pdf")
print(f"Report written to {pdf_path}")
```

### Lower-level pipeline stages

```python
from transunion_pdf_engine import parse_credit_report, build_story, render_pdf

report = parse_credit_report(raw_json)   # -> CreditReport (normalized model)
story = build_story(report)              # -> list[Flowable]
render_pdf(story, "output/report.pdf", report=report)
```

Use these when you want to inspect or transform the parsed model before
rendering (e.g. redact fields, add custom sections, or unit test parsing in
isolation from PDF rendering).

### Optional: mask account numbers

```python
generate_report(raw_json, "output/report.pdf", mask_account_numbers=True)
```

By default account numbers render in full, matching the reference report.
Pass `mask_account_numbers=True` to show only the last 4 digits.

### Django integration

```python
from services.transunion_pdf_service import TransUnionPDFService

service = TransUnionPDFService()
pdf_path = service.generate_for_customer(customer, raw_json)
```

`TransUnionPDFService` resolves output paths against `django.conf.settings.MEDIA_ROOT`
when Django is configured, and falls back to a local `output/` directory
otherwise (e.g. under plain `pytest`).

## Project layout

```
transunion_pdf_engine/
    __init__.py       # public API: generate_report, parse_credit_report, build_story, render_pdf
    parser.py         # raw JSON -> normalized CreditReport (defensive, never raises)
    models.py          # dataclasses: CreditReport, Customer, Account, Enquiry, ...
    constants.py       # TransUnion CIBIL code tables (account type, state codes, ...)
    theme.py           # page geometry, colors, embedded local fonts, logo path
    styles.py           # ReportLab ParagraphStyle / TableStyle definitions
    helpers.py          # safe extraction + formatting + flowable-builder helpers
    generator.py        # build_story() / render_pdf() / generate_report()
    sections/            # one render(story, report, styles) module per report section
    assets/               # local-only: cibil-logo.svg, Montserrat/, Poppins/, Roboto/
services/
    transunion_pdf_service.py  # ONLY file allowed to import Django
tests/
    test_parser.py      # parsing correctness + malformed-input safety
    test_generator.py   # story assembly + PDF rendering
    test_pdf.py          # end-to-end PDF content validation via pypdf
input/
    transunion_response.json   # real fixture used by the test suite
output/
    report.pdf            # generated by generate_report() / tests
docs/
    JSON_TO_PDF_MAPPING.md    # every rendered field traced to its exact JSON path
    sample_report.pdf.pdf     # reference layout
```

## Running tests

```bash
python -m pytest -v
```

37 tests cover: parsed field correctness against the real fixture (name,
DOB, gender, PAN, CKYC, score, control number, account counts and values,
enquiry counts and values), malformed/missing/null/`-1`/single-item-instead-
of-array JSON shapes, PDF generation and page count, presence of every
account number and enquiry in the rendered text, correct ₹ glyph rendering,
account-number masking, and an explicit check that no sample customer PII is
hardcoded anywhere in `transunion_pdf_engine/`.

## Design notes

- **Parser never raises.** Every extraction step is defensive; a malformed
  sub-tree is logged as a warning (`CreditReport.warnings`) and skipped
  rather than crashing the whole report. See `docs/JSON_TO_PDF_MAPPING.md`
  for how TransUnion's sentinels (`-1`, `-1.00`, `""`, `null`) and its
  XML-derived "single item collapses to an object instead of a 1-item list"
  quirk are normalized.
- **Code tables, not guesses.** TransUnion's enum-like fields
  (`{"symbol": "02", "description": ""}`) arrive with an empty description
  in this feed. `transunion_pdf_engine/constants.py` translates every `symbol` using
  standard published TransUnion CIBIL code tables, with a safe
  `"Unknown (code)"` fallback for anything not covered -- never a crash, never
  a fabricated label.
- **Visual system matches the reference closely**: a cyan CIBIL wordmark
  (rendered from `assets/cibil-logo.svg` via `svglib`), plain cyan uppercase
  section labels (no filled banner), light-gray cards for detail sections,
  a semicircular score gauge with a needle, single-column
  "Label ................ Value" rows for account details, green/red bullet
  dots for OPEN/CLOSED ACCOUNTS, and a split running header (timestamp +
  "CIBIL Report") / footer (generator credit + page X/Y) on every page.
  Section order, headings, and every field match the reference; page count
  is not forced to match (~14 pages vs. the reference's 11 for this
  fixture) because related content -- an account's header, its field list,
  and its payment-status block -- is kept together across page breaks
  (`reportlab.platypus.KeepTogether`) rather than compressed to hit a fixed
  count.
- **Fonts are embedded from local assets only**, never system fonts, never
  downloaded: Montserrat SemiBold/Bold for titles and section headings,
  Poppins Bold for the big numeric score, Roboto Regular/Medium/Bold for
  everything else (`theme._register_fonts()`). All three ship the Indian
  Rupee glyph (U+20B9), so `₹` always renders correctly; if an asset file is
  ever missing, the engine falls back to base-14 Helvetica and an `"Rs. "`
  currency prefix rather than crashing or showing a broken glyph box.
- **The logo degrades gracefully.** If `cibil-logo.svg` can't be parsed for
  any reason, `score_section.py` falls back to a plain text "CIBIL / Part of
  TransUnion" brand block instead of failing the whole render.
